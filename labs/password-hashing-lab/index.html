Legacy Fast Hashes

Early systems stored passwords with fast, unsalted hashes like MD5, SHA1, and NTLM. These designs made sense before large-scale GPU cracking, but they are now trivial to attack.

Key ideas
  • Fast hashes are ideal for integrity checks, not password storage.
  • Unsalted hashes allow precomputed rainbow tables and hash reuse.
  • Any remaining MD5, SHA1, or NTLM password storage should be treated as high risk.
Defender guidance
  • Inventory where fast hashes are still used for passwords.
  • Plan a migration path to slow, salted KDFs.
  • Assume that legacy fast hashes are already exposed or crackable.
